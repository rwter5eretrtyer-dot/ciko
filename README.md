# Ciko

Минималистичный онлайн-кинотеатр с комнатами для совместного просмотра.

## Запуск на Windows

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и дождитесь состояния **Engine running**.
2. Распакуйте архив так, чтобы получить папку `ciko`.
3. Дважды щёлкните **START_CIKO.bat** в этой папке.
4. Откройте `http://localhost:8080`. Обычно стартовый файл открывает сайт сам.

При первом запуске автоматически создаётся `.env` с уникальными ключами. Поднимаются PostgreSQL, REST API и frontend. Запуск повторно использует существующую базу данных.

**Если в `C:\ciko` уже работает старая версия:** сперва выполните в её терминале `docker compose down` (без `-v`), скопируйте файлы новой версии поверх старых, сохранив `.env`, и запустите `START_CIKO.bat`. Тома Docker сохранят данные.

Ручной запуск в PowerShell из папки `ciko`:

```powershell
# Первый раз, если не использовали START_CIKO.bat:
Copy-Item .env.example .env
# Замените оба TOKEN_SECRET на разные случайные строки длиной 32+ символа.
docker compose up --build -d
# Проверка:
docker compose ps
docker compose logs --tail=100 api
```

Остановить проект: `STOP_CIKO.bat` или `docker compose down`. Не используйте `docker compose down -v`: это удаляет данные.

## Что есть

- Каталог фильмов/сериалов, серверный поиск, фильтры и пагинация.
- Регистрация, access/refresh JWT, роли viewer/editor/admin, профиль и избранное.
- Просмотр собственных MP4/WebM/OGG и поддерживаемых ссылок YouTube/Vimeo.
- **Комнаты**: любой зарегистрированный зритель создаёт комнату, выбирает фильм, загружает своё видео или вставляет ссылку, приглашает по коду, общается в чате.
- Для прямых видео действует синхронизация паузы, запуска и перемотки. Управляет создатель, другие участники следуют за его временем (обновление раз в 2,5 с). Браузер может попросить нажать кнопку для воспроизведения со звуком.
- YouTube/Vimeo встраиваются в комнату, но **не синхронизируются**: каждый участник управляет таким плеером самостоятельно.
- Редактор и администратор управляют публичными карточками фильмов. Администратор управляет аккаунтами и видит статистику.

## Демо-вход (только локально)

| Роль | Email | Пароль |
|---|---|---|
| Зритель | `viewer@ciko.local` | `CikoDemo2026!` |
| Редактор | `editor@ciko.local` | `CikoDemo2026!` |
| Администратор | `admin@ciko.local` | `CikoDemo2026!` |

`SEED_DEMO=true` добавляет несколько демонстрационных карточек. Прямое открытое видео есть только у фильма «После света». Остальные карточки можно наполнить через **Профиль → Студия** под аккаунтом редактора.

## API и структура

- Сайт: `http://localhost:8080`
- Проверка API: `http://localhost:8080/api/health`
- Swagger: `http://localhost:8080/api/docs`
- Схема БД: `backend/migrations/001_initial.sql` и `backend/migrations/002_rooms.sql`
- Новые API комнат: `backend/src/routes/rooms.routes.ts`
- Интерфейс комнат: `frontend/src/pages/RoomsPage.tsx`, `frontend/src/pages/RoomPage.tsx`
- Остальные документы: `docs/`.

Код снабжён русскими комментариями в ключевых местах. Сервис хранит видео в Docker volume `video_uploads`, а данные в `postgres_data`. Загружайте только видео, которыми вправе распоряжаться. Не делайте демо-пароли доступными в интернете.

## Тесты

В окружении с Node.js 22 и работающим PostgreSQL:

```sh
cd backend && npm install && npm run build && npm test
cd ../frontend && npm install && npm run build && npm test
```

Интеграционные тесты API используют отдельную тестовую PostgreSQL (`backend/tests/integration.test.ts`). CI описан в `.github/workflows/ci.yml`. Публичный деплой, реальный прогон CI и макеты в Figma необходимо подтвердить отдельно.
