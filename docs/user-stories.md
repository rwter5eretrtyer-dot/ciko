# Ciko — пользовательские истории и критерии приёмки

Формат: **«Как [роль], я хочу [действие], чтобы [ценность]»**. Для индивидуального проекта предусмотрено не менее 10 историй; ниже — 16. Перенесите их в GitHub Projects, привяжите к коммитам и PR.

## Definition of Done

1. Рабочая логика API и понятные сообщения ошибок.
2. Права доступа проверены запросами в обход интерфейса.
3. Написан минимум один соответствующий тест; CI зелёный.
4. Изменение оформлено feature-веткой, PR и самопроверкой.
5. Пользовательский сценарий показан вручную в браузере.

Текущий документ — готовые истории, но **не** свидетельство выполнения всех критериев: работающий запуск и CI требуется зафиксировать отдельно.

## Комнаты для совместного просмотра

11. Как зритель, я хочу создать комнату с фильмом из каталога, чтобы смотреть его с друзьями. Критерии: после создания появляется уникальный код; создатель уже числится участником.
12. Как зритель, я хочу загрузить своё видео или вставить поддерживаемую ссылку, чтобы смотреть собственные материалы. Критерии: сервер проверяет MIME-тип и размер файла; ссылка проверяется на сервере.
13. Как приглашённый зритель, я хочу войти по коду, чтобы смотреть вместе с создателем. Критерии: неизвестный код возвращает 404; членство сохраняется в БД.
14. Как участник, я хочу видеть общий чат, чтобы общаться во время просмотра. Критерии: сообщения видны только участникам, текст ограничен 500 символами.
15. Как создатель, я хочу управлять паузой и перемоткой, чтобы гости смотрели тот же момент. Критерии: гостю запрещено менять состояние; клиенты сверяют позицию с сервером.
