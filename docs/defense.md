# Ciko — план защиты и сценарий презентации

По заданию нужно **8–12 слайдов, демо-видео до 5 минут** и живая демонстрация работающего приложения. Ниже — содержание 10 слайдов. Для сдачи перенесите его в PPTX/PDF, добавьте реальные скриншоты.

## Презентация — 10 слайдов

1. **Ciko — кино без лишнего.** Название, автор, группа, дата. Чёрный фон, хаки и бордовый акценты.
2. **Проблема.** Сложно удобно управлять личным видеокаталогом, ролями, просмотрами, контентом.
3. **Цель.** Рабочий MVP стримингового приложения с безопасным API, ролями, БД и развёртыванием.
4. **Для кого.** Зритель, редактор, администратор — три самостоятельных сценария.
5. **Возможности.** Каталог, поиск, плеер, прогресс, избранное, отзывы, загрузка видео и ссылки.
6. **Архитектура.** React/TS → Nginx → Express/TS → PostgreSQL + upload volume; Docker Compose.
7. **ER и API.** 10 таблиц, M:N жанры, Swagger, серверная фильтрация.
8. **Безопасность.** bcrypt, JWT access/refresh, RBAC на сервере, валидация, ограничения файлов.
9. **Качество.** Unit/Integration/Frontend-тесты, CI GitHub Actions, результаты после реального запуска.
10. **Демонстрация и итоги.** Публичная ссылка, QR на репозиторий, статус требований, развитие проекта.

## Демо-скрипт (7 минут)

**0:00–0:45.** Открыть главную страницу Ciko, показать цветовую систему и адаптивную вёрстку.

**0:45–1:30.** Открыть каталог, найти фильм по названию, изменить сортировку, фильтр жанра и пагинацию.

**1:30–2:20.** Войти как `viewer@ciko.local`. Добавить фильм в избранное, открыть профиль, добавить отзыв.

**2:20–3:15.** Воспроизвести демо-видео первого фильма, поставить на паузу и показать сохранение прогресса. Для чужих роликов без лицензии использовать только тестовый клип.

**3:15–4:30.** Переключиться на `editor@ciko.local`, открыть Студию. Загрузить небольшой собственный MP4 и постер (заранее подготовить), создать карточку, показать плеер.

**4:30–5:50.** Войти как администратор, показать управление пользователями и ролями, аудит и график.

**5:50–7:00.** Показать Swagger, `docker compose up`, GitHub Actions, примеры тестов и ограничения RBAC. Дальше — вопросы комиссии.

## Вопросы на защите

- **Почему выбран TypeScript?** Типы сокращают ошибки между клиентом и сервером.
- **Зачем JWT access + refresh?** Короткая жизнь access и возобновление сессии через cookie.
- **Какой алгоритм хранения паролей?** bcrypt с 12 раундами, оригинальные пароли не сохраняются.
- **Как защищён CRUD?** Серверная проверка через `requireAuth` и `requireRole`, HTTP 403 при отсутствии прав.
- **Что такое миграции?** Воспроизводимые версии схемы БД, фиксируемые в `schema_migrations`.
- **Как загрузить видео?** Multer проверяет MIME и размер, сохраняет под UUID, возвращает путь.
- **Что делает CI?** Автоматически запускает проверки PR и проверяет сборку образов.

**Не называйте численные результаты тестов или публичный адрес, пока реально не получили подтверждение.**
