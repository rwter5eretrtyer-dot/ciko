# Как Ciko работает: объяснение простыми словами

## 1. Что делает браузер

`frontend/src/App.tsx` выбирает экран по URL. Например `/catalog` показывает `CatalogPage.tsx`, а `/movie/:id` — `MoviePage.tsx`. Любые данные идут не из HTML, а через `frontend/src/lib/api.ts`: функция `api()` делает `fetch('/api/...')` и возвращает `data`.

## 2. Что делает сервер

`backend/src/app.ts` создаёт приложение Express и подключает маршруты. Когда браузер отправляет `GET /api/movies`, маршрут `movies.routes.ts` проверяет фильтры и вызывает `listMovies()` из `repositories/movies.repo.ts`. Репозиторий делает SQL-запрос в PostgreSQL. Сервер возвращает JSON.

## 3. Что делает база данных

PostgreSQL хранит пользователей, фильмы, жанры, связи фильм-жанр, избранное, историю, отзывы, токены и журнал действий. Все изменения структуры идут через `migrations/001_initial.sql`, а `seed.ts` создаёт тестовые записи. Сущности не дублируются: связи 1:N и M:N.

## 4. Регистрация и авторизация

Пароль не записывается напрямую: `bcrypt.hash()` превращает его в хэш. При входе сервер проверяет `bcrypt.compare()`, выдаёт короткий `accessToken` и длинный `refreshToken`. Первый браузер хранит временно в памяти; второй — в `HttpOnly cookie`, недоступной JavaScript. При обновлении refresh предыдущая запись отзывается. Middleware `requireAuth` проверяет токен и читает роль **из базы**, а `requireRole` запрещает недоступную операцию.

## 5. Загрузка видео

В студии редактор выбирает MP4/WebM/OGG. Браузер отправляет `FormData` на `POST /api/uploads?kind=video`. Multer проверяет MIME и размер, генерирует безопасное имя UUID и сохраняет в папку `/app/uploads`. Docker volume `video_uploads` сохраняет его после перезапуска. API возвращает путь вида `/uploads/uuid.mp4`. Этот путь добавляется к фильму. Сторонняя ссылка обрабатывается отдельно — сервер разрешает только HTTP(S), конкретные видеоформаты или embed YouTube/Vimeo.

## 6. Как работает плеер

`MoviePage.tsx` выводит `<video>` для MP4/WebM/OGG либо `<iframe>` для разрешённых YouTube/Vimeo. Каждые ~9 секунд прогресс сохраняется через `PUT /api/me/progress/:id` (для вошедшего пользователя), поэтому фильм можно продолжить позже.

## 7. Что такое CI

`.github/workflows/ci.yml` описывает проверки при push и Pull Request: линтер, unit-тесты, интеграционные тесты с настоящим PostgreSQL, сборка frontend/backend и Docker-образов. На защите можно открыть GitHub Actions и показать зелёные проверки. Пока репозиторий не загружен и workflow не отработал, утверждать об успешном CI нельзя.

## 8. Возможные вопросы преподавателя

**Что такое REST?** Соглашение о запросах HTTP: GET получает, POST создаёт, PUT заменяет, DELETE удаляет.

**Почему SQL-запросы безопаснее?** Мы используем параметры `$1`, `$2`, а не вставляем строку пользователя внутрь SQL.

**Что такое RBAC?** Role-based access control: у каждой роли свой набор прав. Проверка на сервере обязательна.

**Что такое JWT?** Подписанный токен с идентификатором пользователя, который сервер может проверить по секрету.

**Зачем миграции?** Позволяют воспроизводимо создавать и изменять схему БД на разных серверах.

**Чем отличается unit от integration?** Unit проверяет функцию изолированно, integration проверяет весь маршрут и работу с настоящей базой.
