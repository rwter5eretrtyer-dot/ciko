## 1. Введение

В рамках учебной практики разрабатывается Ciko — минималистичная клиент-серверная система управления видеоконтентом. Цель: пройти полный цикл разработки web-MVP, включая анализ предметной области, разработку API, пользовательский интерфейс, хранение данных, тестирование и развёртывание.

## 2. Предметная область

Предметная область — сервисы просмотра и управления легально размещёнными видеоматериалами. Базовые пользователи: зритель, контент-редактор, администратор. Проблема: необходима централизованная среда, объединяющая каталог, просмотр, историю, редакторскую панель и контроль доступа.

## 3. Требования

Функциональные: доступ без авторизации к опубликованным карточкам, регистрация, личный кабинет, просмотр, история, оценки, работа с контентом, пользователями. Нефункциональные: клиент-серверная архитектура, 3 роли, 6+ таблиц, PostgreSQL, Docker Compose, OpenAPI 3, адаптивность, автотесты и CI. Подробнее — `user-stories.md`.

## 4. Архитектура

Frontend реализован на React с TypeScript strict. Backend — Node.js с Express на TypeScript. PostgreSQL хранит данные, Docker Compose объединяет API, frontend и БД. Диаграммы расположены в `architecture.md`.

## 5. База данных

Схема включает `users`, `movies`, `genres`, `movie_genres`, `favorites`, `watch_history`, `reviews`, `refresh_tokens`, `password_reset_tokens`, `audit_logs`. Модель разделяет сущности и предусматривает связи 1:N и M:N. Создание схемы — SQL-миграция `001_initial.sql`.

## 6. Backend

Маршруты Express разделены по предметным областям. Для фильма доступны CRUD, проверка ролей, фильтрация и пагинация. Используются параметризованные запросы PostgreSQL, валидация Zod и единый формат JSON-ответов. API документировано в Swagger.

## 7. Frontend

Созданы страницы: главная, каталог, фильм с плеером, регистрация/вход, профиль, избранное, история, студия, администрирование. Визуальный стиль минималистичный: чёрный, хаки и бордовый. UI адаптируется к мобильным экранам и desktop.

## 8. Безопасность

Пароли хэшируются bcrypt. Для сессий используются access JWT и refresh JWT, который передаётся через HttpOnly cookie и отзывается при обновлении или выходе. Серверная RBAC-проверка предотвращает изменение каталога зрителем. Для загружаемых файлов ограничены MIME-тип и максимальный размер.

## 9. Тестирование и CI

Созданы unit-тесты функций безопасности, интеграционные тесты API с PostgreSQL и тесты React-компонента. Конфигурация GitHub Actions предусматривает lint, тесты и сборки. **Дописать после запуска:** реальные даты, процент покрытия, число успешных тестов, обнаруженные и исправленные дефекты со ссылками.

## 10. Контейнеризация

В `docker-compose.yml` определены web, API, PostgreSQL, два постоянных тома. Проект рассчитан на команду `docker compose up --build`. **Дописать после запуска:** доступный адрес, результаты проверки health и плеера, скриншоты Docker.
